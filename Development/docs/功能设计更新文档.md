# William 功能设计更新文档

> 更新日期：2026-03-14
> 依据文档：`docs/PRD.md`
> 状态：Phase 1 MVP 重构完成

---

## 一、背景与目标

本次更新依据 PRD 中定义的四层系统架构，对项目原有的功能分区进行了系统性重设计。

原有问题：
- 首页（TodayScreen）全部使用 `DEFAULT_HISTORY` 静态 mock 数据，"William noticed" 卡片无法反映真实用户状态
- Story 页（StoryScreen）概念命名与 PRD 中"Journeys"功能分区不一致，两个功能混在一起
- 成长路径（Paths）仅作为 TodayScreen 内的横向轮播展示，缺少独立入口
- 情绪速记入口（MoodScreen）是隐藏路由，用户无法从主导航直接访问
- YouScreen 的周图表使用静态 mock 数据，无洞察展示，无隐私控制入口
- 后端缺少个性化今日数据接口（`/today`）、练习完成记录（`/practices`）和旅程管理（`/journey`）

---

## 二、PRD 四层架构与功能分区对应关系

```
感知层（Perceptual）      → 权限授予、设备信号收集          → YouScreen 隐私设置
情绪防护层（Emotion Guard） → 情绪检测、压力趋势分析           → 后端 behaviorEngine + day_profiles
因果归因层（Causal Intel）  → 模式识别、洞察归因              → /api/user/insights、YouScreen 洞察卡
技能干预层（Skills）       → 练习、冥想、旅程路径、AI对话      → TodayScreen 练习、JourneyScreen、ChatScreen
```

### 3.2 TodayScreen（首页）— 连接真实数据

**功能变更：**
1. **个性化今日信息卡** — 组件加载时调用 `GET /api/user/today`，获取后端计算的 `greeting`、`timeSlot`、`insight`、`practiceReason`、`focusChallenge`、`topTrigger`。
2. **"William noticed" 卡片** — 当选中 `Today` 时展示真实纵向分析的首要 Insight；切到历史日期后会改为该天视角的回顾文案，和顶部日期条、Moments 卡片同步。
3. **William 日程候选区块** — `Planned from William` 迁入 Today，展示由聊天抽取出的待确认未来安排，支持 `Add to Journey / Edit`，删除入口收进编辑弹层。
4. **Moments 卡片迁入 Today** — 原 Journey 的日内 `moments` 列表迁到 Today，与顶部日期条联动，支持默认事件和确认后计划事件的统一编辑；顶部 `Calendar` 入口改为弹出式日期选择器，替代原生日期输入。
5. **移除时段练习区块** — `midday / morning / evening` 练习区块从 Today 移到 Journey，Today 只保留更贴近“今天发生了什么”的信息。
6. **移除 Paths 轮播** — Paths 内容迁移到 JourneyScreen，今日首页保持信息聚焦，符合 PRD"每次一个主要行动"的原则。

**数据流：**
```
挂载 → GET /api/user/today → store.todayFeed → 渲染 Today 视角的 "William noticed" + Journal
挂载 → GET /api/user/insights → store.longitudinal → 洞察辅助信息
挂载 → GET /api/user/history?days=365 → store.history → Today 的 Calendar 入口 + 日期条 + Moments 卡片
挂载 → GET /api/journey/schedule-candidates?status=candidate|confirmed → 候选区块 + 计划事件并入 Moments
点击 Calendar 选日期 → 更新 `selectedDateKey + visibleMonth` → "William noticed" 切到对应日期视角
```

### 3.2.1 William Chat 记忆系统（新增）

当前 `William` 页的聊天能力已经从“只存聊天记录”升级为“共享记忆底座 + 角色化读取”：

- **共享底座**
  - `William Classic` 和 `Digital Expert` 共用 `shared_core` / `shared_session`
- **角色偏置**
  - `Classic` 额外读取 `classic_bias`
  - `Digital Expert` 额外读取 `expert_bias`
- **写入策略**
  - 每轮先落 `chat_messages`
  - 再更新 `session_memories`
  - 最后抽取长期记忆写入 `user_memories`
- **读取策略**
  - 先读共享长期记忆
  - 再读当前 session 摘要
  - 最后叠加角色偏置和最近几轮原始消息

**当前目标：**

1. 用户在 `Classic` 和 `Digital Expert` 间切换时不断片
2. 长对话不会只靠最近几轮原始消息硬撑
3. 长期记忆支持去重、抑制脏记忆、回溯抽取来源
4. 正式用户侧也能看到 William 记住了什么，并对长期记忆做最基础控制
5. 用固定审计矩阵持续检查“抽取是否变脏、prompt 是否变胖、干预归因是否失真”

**当前记忆层对应表：**

| 层级 | 表 | 说明 |
|------|----|------|
| 原始消息 | `chat_messages` | 用户/助手逐条消息 |
| 会话记忆 | `session_memories` | `shared_session / classic_bias / expert_bias` 摘要 |
| 长期记忆 | `user_memories` | `shared_core / classic_bias / expert_bias` 长期条目 |
| 进行中事项 | `user_active_loops` | 用户当前正在推进、临近处理或反复卡住的事项 |
| 干预结果 | `intervention_outcomes` | 每次建议/脚本/练习型回复之后的接受与跟进结果 |
| 干预偏好 | `user_intervention_preferences` | 聚合“哪类支持方式对这个用户更有效” |
| 调试事件 | `memory_events` | 每次创建、更新、重建、重抽取的事件日志 |

**当前正式用户侧控制（V1）：**

- `Memory Center`
  - 设置页可查看当前长期记忆列表
  - 设置页可查看当前 `active loops`
  - 设置页可查看“更容易有效 / 较少起作用”的支持方式摘要
  - 可删除单条长期记忆
  - 可把某个 active loop 标记为已完成
  - 可通过 `users.memory_enabled` 暂停 William 对长期记忆的读取和写入
- `Temporary chat`
  - 仍走同一条 `chatService` 主链路
  - 不读取 `user_memories / session_memories`
  - 不写入新的长期/会话记忆
  - 不出现在正式聊天历史里
  - 当前 V1 仍保留 temporary session 的原始 `chat_messages` 以支撑当轮连续性；它不是数据库级无痕销毁

**当前算法治理（新增）：**

- 后端提供 `npm run audit:prompt`
- 后端提供 `npm run audit:memory`
- 它直接复用 `memoryService / composePromptContext / mentalSupportService / interventionService`
- 当前审计关注 4 类问题：
  - 记忆/loop 误抽取
  - 支持模块误路由
  - prompt 过度堆叠
  - 干预效果偏好被无关事件污染
- `audit:memory` 额外验证：
  - 规则 hard filter 之后的模型判义是否稳定
  - `memory_candidates` 是否只在重复证据足够时 promotion
  - classifier 不可用时是否正确回退到规则抽取

### 3.2.2 William 页语音入口（新增）

`William` 页右上角和右下角现在分成两种语音能力：

| 入口 | 目标 | 技术路径 |
|------|------|---------|
| 右上角 `📞` | 语音通话 | `MediaRecorder -> /api/voice/call-turn -> STT -> chatService -> reply` |
| 右下角 `🎙️` | 语音转文字输入 | `SpeechRecognition` 优先；不支持时 `MediaRecorder -> /api/voice/transcribe` |
| 底部 `+ -> Start Listening` | App 内后台监听开关 | `AppShell + MediaRecorder -> /api/voice/ambient-listening-audio` 跨页面持续监听 |

**产品原则：**

1. 语音不单独维护第二套记忆系统
2. 所有语音最终先转成文本
3. 文本再进入和普通输入相同的多轮记忆链路
4. `Start Listening` 属于 App 内全局监听，不是单轮语音输入
5. 当前 V1 只保证单页 app 前台持续监听，不承诺浏览器真正后台或锁屏后的持续采集

这保证了：

- 文字和语音之间可以无缝切换
- 通话里说过的内容，回到输入框继续打字时仍然能接上
- `William Classic` 和 `Digital Expert` 的角色切换不会因为输入形态不同而断片
- 用户开启监听后仍可继续使用 `Today / Journey / You`
- 每个音频片段会异步调用 `POST /api/voice/ambient-listening-audio`
- 后端会通过 `voice_service.py:/analyze` 跑音频分析，得到 `voice_stress / speech_pace / stability / vocal_vitality`
- 分析结果会写入 `ambient_listening_events`，并更新 `day_profiles.ambient_stress_avg / ambient_stress_peak`
- `Today / You` 展示层会把 `ambient_stress_avg` 作为 voice signal 融合进 stress 展示；当前不直接覆盖 `composite_stress`
- `TodayFeed / insights` 生成层也改成使用融合后的 stress 口径，因此 `William noticed` 和纵向分析会自然感知 voice signal

### 3.2.3 William 页附件入口（新增）

`William` 页底部 `+` 面板中的 `Photo / File` 现在不是单纯上传，而是进入可理解的附件链路：

| 入口 | 目标 | 技术路径 |
|------|------|---------|
| `📷 Photo` | 上传照片 / 截图 | `multipart/form-data -> /api/chat/message -> image summary + OCR -> chatService` |
| `📄 File` | 上传 PDF / DOCX / TXT 等文件 | `multipart/form-data -> /api/chat/message -> text extract + summary -> chatService` |
| `🔗 AI Chat` | 导入公开分享页 / 网页 | `URL -> /api/chat/message -> fetch + readability summary -> chatService` |

**系统行为：**

1. 原文件保存到 `uploads/`
2. 结构化结果写入 `chat_attachments`
3. 当前附件摘要进入本轮模型上下文
4. 最近附件摘要在后续追问时继续作为会话上下文被读取
5. 从附件中提炼出的稳定事实沿用现有记忆系统写入长期/会话记忆

**URL 导入边界：**

- 对 `ChatGPT / Claude / Gemini` 公开分享页，优先按 provider 规则提取“用户 / 助手”轮次
- V1 只支持公开可访问的分享页或普通网页
- 不支持需要登录的私有 Claude / ChatGPT / Gemini 会话页
- 后端需要做内网地址拦截、响应大小限制和超时控制

### 3.3 JourneyScreen（旅程页）— 替换 StoryScreen

**功能区域：**

| 区域 | 功能 |
|------|------|
| **激活旅程卡** | 展示当前进行中的旅程进度 |
| **Story 视图** | 情绪故事可视化 |
| **当前时段练习** | 展示 `morning / midday / evening` 推荐练习并支持完成打卡 |

**具体变更：**
1. **激活旅程进度卡** — 顶部展示当前正在进行的旅程标题、步骤进度条和 `Continue` 按钮，直接跳转 `PathDetailScreen`。
2. **William 日程候选区块（迁移）** — `Planned from William` 从 Journey 顶部迁移到 Today：
   - 来源于 `William` 对话中的未来事件抽取
   - 抽取优先走 LLM 判定 + 结构化解析，而不是纯关键词拆分
   - 只有模型认为“值得显示为候选”的未来安排才会进入 UI；不会只因“今天/明天 + 一个动作”就直接生成
   - 展示标题、时间、地点、参与人和置信度
   - 支持 `Add to Journey / Edit`
   - 删除入口统一收进 `Edit moment` 弹层
3. **情绪故事可视化** — 保留漫画网格设计，但日期栏优先使用来自 `GET /api/user/history` 的真实数据（`composite_stress`、`mood_avg`），回退使用 `DEFAULT_HISTORY`。
4. **当前时段练习区块（迁入）** — 原 Today 的 `morning / midday / evening` 练习区块迁到 Journey：
   - 展示当前时段推荐练习和时长、类型
   - 点击勾选会调用 `POST /api/user/practices`
   - 完成后更新 XP 和本地完成状态
   - 练习卡仍可跳转到 William
5. **旅程数据加载** — 挂载时调用：
   - `GET /api/journey` 拉取旅程注册状态
   - `GET /api/user/today` 拉取当前时段和练习推荐理由

**数据流：**
```
挂载 → GET /api/user/history?days=7 → store.history → 日期选择器 + 故事视图
挂载 → GET /api/journey → store.journeyEnrollments → 激活旅程卡
挂载 → GET /api/user/today → 当前时段练习 + practiceReason
打勾 → POST /api/user/practices → day_profiles 更新 + XP 奖励
点击 Continue → nav('/path/:idx')
```

### 3.4 YouScreen（个人页）— 添加真实洞察和隐私控制

**新增功能区块：**

1. **实时周图表** — 优先使用 `GET /api/user/history` 的真实数据（`composite_stress`、`mood_avg`）渲染；无数据时保持原始 mock 样式。
2. **数据天数统计** — 顶部 Stats 栏将原来的固定"62 STABILITY"替换为来自 `longitudinal.dayCount` 的实际数据积累天数。
3. **William's Insights 区块（新增）** — 当后端 Insights 有内容时显示：
   - **趋势洞察**（warning/positive）：显示压力上升/下降趋势，带颜色区分
   - **周期性模式**：显示哪天最难/哪天最平静
   - **触发词识别**：展示高压日反复出现的话题（如"meeting""deadline"），帮助用户理解情绪触发规律
4. **Privacy & Data 区块（新增）** — 以开关列表替换原来底部第二个 Tribe 占位卡片，显示 5 项权限（麦克风/通知/健康/日历/位置）的开关状态，支持用户随时调整，底部注明"所有信号经用户授权处理，随时可删除数据"。
5. **Wellbeing 摘要优化** — 睡眠状态改为读取 `store.sleep` 真实值；压力等级改为根据 `insights.insights[0].severity` 动态显示 High/Med/Low。

**数据流：**
```
挂载 → GET /api/user/history?days=7 → store.history → 周图表
挂载 → GET /api/user/insights?days=14 → store.longitudinal → Insights 区块 + Wellbeing 数值
切换权限 → store.togglePerm() → 本地状态更新（后续可接 POST /api/user/profile 持久化）
```

## 四、后端新增 API 接口

### 4.1 `GET /api/user/today`

**用途：** 构建个性化今日数据包，供 TodayScreen 首屏使用

**响应结构：**
```json
{
  "greeting": "Good morning, Alex",
  "timeSlot": "morning",
  "insight": {
    "title": "Stress is rising",
    "detail": "From 4.2 to 7.1 over 5 days.",
    "type": "warning",
    "severity": "high"
  },
  "practiceReason": "Start grounded — sets the tone for your day.",
  "focusChallenge": "Anxiety",
  "topTrigger": "meeting",
  "patterns": [
    { "type": "weekly", "detail": "Mondays hardest (7.2). Saturdays calmest (2.1)." }
  ],
  "journeyProgress": {
    "journey_id": "anxiety",
    "current_step": 2
  }
}
```

**数据来源：** `users` + `day_profiles`（最近 14 天）+ `behaviorEngine.buildTodayFeed()` + `journey_enrollments`

### 4.2 `POST /api/user/practices`

**用途：** 记录用户完成一项练习，奖励 XP，更新当日 day_profile

**请求体：**
```json
{ "practiceId": "anchor", "timeSlot": "morning" }
```

```json
{ "ok": true, "xpAwarded": 15 }
```

**副作用：** `users.xp += 15`，`day_profiles.practice_count += 1`，`day_profiles.practices_done` 追加 practiceId

### 4.2.1 用户侧记忆控制（`/api/user/*`）

这些接口属于正式产品能力，不再只依赖 debug route：

| 方法 | 路径 | 功能 |
|------|------|------|
| `GET` | `/api/user/memories` | 获取当前用户可见长期记忆、active loops、intervention 效果摘要，以及 `memory_enabled` 开关状态 |
| `POST` | `/api/user/memories/:memoryId/status` | 更新单条长期记忆状态，当前产品侧主要用于标记为 `deleted` |
| `POST` | `/api/user/active-loops/:loopId/status` | 更新单条 active loop 状态，当前产品侧主要用于标记为 `resolved` |

**配套前端语义：**

- 设置页提供 `Memory Center`
- `Memory Center` 会把 `active loops` 和 `saved memories` 分开呈现
- `Memory Center` 也会显示 William 当前学到的支持方式效果摘要
- 聊天页提供 `Temporary chat` 开关
- 若关闭 `memory_enabled`，William 仍可使用当前轮原始消息与显式档案，但不会继续读写长期记忆
- `DELETE /api/chat/history` 只清正式聊天历史视图，不等于清空长期记忆，也不是 temporary chat 的替代品

## 五、数据库变更

### 新增表 1：`journey_enrollments`

```sql
CREATE TABLE journey_enrollments (
  id           BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id      BIGINT UNSIGNED NOT NULL,
  journey_id   VARCHAR(30) NOT NULL,
  current_step TINYINT UNSIGNED DEFAULT 0,
  started_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  completed_at TIMESTAMP NULL,
  UNIQUE KEY uk_user_journey (user_id, journey_id)
);
```

**用途：** 追踪用户对每条旅程的注册状态和进度。

### 新增表 2：`practice_completions`

